# Test Report: Document Forgery & Tampering Detection Pipeline

## 1. Report Scope

This test report corresponds to the stable assignment submission branch:

```txt
ml-first-api
```

This branch implements the core assignment pipeline:

- forensic feature extraction,
- feature store generation,
- baseline RandomForest ML model,
- rule-based explainability,
- FastAPI `/doc/analyze` endpoint,
- structured JSON output.

An Aadhaar-focused OCR/semantic validation branch is being developed separately and is not treated as the main stable submission in this report.

---

## 2. Dataset Summary

The dataset used in the stable submission contains synthetic document samples across multiple document categories.

```txt
Total documents: 70
Authentic documents: 34
Forged documents: 36
```

The document categories include:

```txt
Aadhaar-style documents
PAN card-style documents
Bank statements
Certificates
ID cards
```

The dataset is synthetic. No real official/private documents are used in the submitted repository.

In this project:

```txt
Authentic = untampered synthetic/base document
Forged = deliberately modified/tampered synthetic document
```

The system detects tampering patterns in synthetic document samples. It does not verify the legal genuineness of real Aadhaar cards, PAN cards, bank statements, certificates, or ID cards.

## 4. Extracted Features

The model uses 23 numeric training features.

The features used during training were:

```txt
file_size_kb
image_width
image_height
aspect_ratio
mean_brightness
brightness_std
contrast_score
blur_score
edge_density
noise_score
sharpness_variation
jpeg_artifact_score
compression_ratio_estimate
contour_count
dark_pixel_ratio
white_pixel_ratio
pdf_page_count
pdf_object_count
metadata_missing_count
suspicious_creator_flag
modified_after_created_flag
visible_text_length
embedded_image_count
```

These features cover the following forensic groups.

### 4.1 Visual Forensics

```txt
noise_score
sharpness_variation
blur_score
edge_density
contour_count
dark_pixel_ratio
white_pixel_ratio
mean_brightness
brightness_std
contrast_score
```

These features help detect visual inconsistencies, pasted regions, unusual texture differences, blur changes, edge inconsistencies, and abnormal pixel distributions.

### 4.2 Compression Forensics

```txt
jpeg_artifact_score
compression_ratio_estimate
file_size_kb
```

These features help detect repeated compression, edited/exported regions, and abnormal file-size-to-image-size behavior.

### 4.3 Metadata Forensics

```txt
metadata_missing_count
suspicious_creator_flag
modified_after_created_flag
```

These features are primarily useful for PDFs and metadata-bearing documents. They indicate missing metadata, suspicious creator/editor software, and creation/modification timestamp differences.

### 4.4 Structural Features

```txt
pdf_page_count
pdf_object_count
visible_text_length
embedded_image_count
```

These features help capture PDF structure, object count, embedded image presence, and extractable text size.

## 8. Explainability Module

The explainability module is implemented in:

```txt
app/evidence_generator.py
```

It produces human-readable forensic evidence grouped into anomaly categories.

The evidence categories are:

```txt
visual_anomalies
compression_anomalies
structural_anomalies
metadata_anomalies
```

Example evidence messages include:

```txt
High sharpness variation detected across image regions, which may indicate pasted or edited areas.
High noise variation detected, which may indicate inconsistent image generation or editing.
High JPEG artifact score detected, suggesting possible repeated compression or editing.
Low white pixel ratio detected, suggesting unusual background or document formatting.
Several PDF metadata fields are missing.
Suspicious creator or producer software detected in metadata.
```

The final API decision uses the trained ML classifier as the primary classifier. Rule-based evidence is used as supporting forensic explanation.

## 18. Limitations

The current stable version has the following limitations:

1. The dataset is small and synthetic.
2. The model is not trained on real-world official documents.
3. The system detects tampering patterns, not legal genuineness.
4. OCR-based semantic validation is not part of the stable `ml-first-api` branch.
5. Advanced Aadhaar-specific semantic validation is being explored separately.
6. Full pixel-level heatmap localization is not implemented in the stable branch.
7. Full cryptographic digital signature verification is not implemented.
8. Font inconsistency detection is limited, especially for image-only documents.
9. PDF layer inconsistency detection is approximated using structural indicators such as object count and embedded image count.
10. The ML model may misclassify very subtle or cleanly edited documents if the extracted visual features do not change strongly.
